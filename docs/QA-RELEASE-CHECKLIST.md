# Peek 测试与发布清单

每次改完默认发版：先测试，再发布。仅在本次明确要求先看效果、仅本地或不发布时例外。必测项未通过或未执行就停在候选阶段；修复或补测后再继续。不得把夹具、旧包或单张样例图当作实机验收。

当用户明确要求直接发布指定现成候选、无需复测时，仅限当次例外：不重打包，核对原文件的版本与 SHA-256，保留现有结果并说明哪些项目没有通过或没有复验。不影响下一版的验收门槛。

## 每版测试流程

1. **锁定候选**：先拉取并核对 `1159112519/Peek` 的默认分支、标签与 Release。使用未占用的递增版本号，统一关于页、EXE、安装器、版本日志和更新源；从干净且可追溯的源码生成便携 EXE 与 Inno 安装 EXE，记录版本、源码提交、两包 SHA-256 及测试环境。所有检查使用这份最终产物；重打包后按影响重验，不用旧包截图、不覆盖正在使用的安装。
2. **设置和桌面**：用隔离配置启用浅色、深色和跟随系统，检查常规页外观切换器和桌面页。按 1×1、2×2、3×3 拖动预览边缘，并检查窄窗、还原后保存、滚动、裁切、列间留白、名称与数字位置。在实际桌面窗口和预览分别截图；固定样本注明，不当作硬件实测。
3. **任务栏被应用挤压**：先用最终构建的原生渲染器逐帧测试 3→2→1→3、短时间收缩后立即反向。检查留下的列是否倒退、离场列是否反复出现、是否裁切到 Explorer 按钮位置、恢复后是否回到完整布局。保留逐帧数据和截图，目视检查不能只看列数或静止帧。有可用的隔离 Explorer 会话时，再通过打开/关闭不同任务栏应用分组实测，检查最后状态、闪烁和回弹。被现有任务栏实例占用、任务栏左对齐或没有足够可验证空间时，记录未完成的实机项目，不替换用户正在运行的组件和不改 Windows 配置。
4. **检查非目标回归**：设置保存重开、浅深色可读性、同类控件尺寸和圆角、数值/单位相对位置、切页。常规的两个监测开关各自切换并保存重启，关闭不清空槽位。组件库分别核对内存百分比和已用容量，在 `14.1 G` 等含窄字形、小数点的样本中检查笔画、单位留白和裁切；组件库和实时预览分开取证：桌面分别放入内存（设置为已用容量）和已用内存，两行 `14.1 G` 都检查浅深色横向墨迹间隔，不得只验组件库。网络和存储两页组件库用 K/s、M/s 检查单位字母与数字可见底边、单位留白；顶部标签按整个导航的文字中线检查，保持共同基线。任务栏和桌面的参数库分类统一使用较小的 12 px 控件文字，核对同类读数字号，并分别检查两个页面的视觉中线。延迟与丢包状态需区分未开启、等待应答、样本不足、无网关、未应答和已有读数；从未收到过网关应答时，不显示 0% 或 100% 丢包。采集测试区别固定样本、系统实时读数和硬件不支持的指标。
5. **验收记录**：先重跑本版改动及用户报告的原始问题，再执行下方安装、菜单、颜色、升级的回归。逐项记录通过、失败或未覆盖及证据路径，区分实际打包程序、测试夹具和真实 Windows／Explorer 操作。失败或关键项未覆盖，停止正式发布。

入口：同目录树的 `tests/peek-desktop-smoke.mjs`、`tests/peek-preview-clarity.mjs`、`tests/PeekDesktopLayoutProbe.cs`、`tests/peek-desktop-layout-pixels.mjs`、`tests/PeekTaskbarSqueezeProbe.cs`。原生压缩夹具使用确定的可用宽度序列，不代替真实应用按钮占位测试。

桌面中文底边：用窗口夹具 PeekDesktopLayoutProbe.cs 和 peek-desktop-han-pixels.mjs 检查浅深色的「内存 89%」「已用 13.9 G」、中文「显卡」与自定义名称有值和缺测切换时是否仍贴同一数字底边。用最终包预览重复检查，验证英文 GPU/CPU、横杠、字号、横向位置、数字和单位保持原样。

## 正式版更新回归

- 用旧版本和不同版本的实际打包 EXE，在隔离目录验证「检查更新」原位切换为「安装并重启」：只有一个更新按钮，轮廓、大小与位置不变，浅深色均不裁切。下方不增加下载或安装按钮。
- 未应用的设置先处理；点一次后验证下载、校验、旧进程退出、安装、新进程启动、设置保留。分别覆盖便携和静默安装夹具、错误校验值及再次尝试。安装升级必须在验证过 SID 的临时 Windows 用户中执行；只改安装目录不能隔离开始菜单、桌面快捷方式和卸载登记。用安装有效载荷清单校验已装宿主，不能用便携启动器的哈希。不要把夹具当作真实 GitHub 下载或生产目录覆盖。
- 发版前用上一公开版与本次候选做隔离升级回归；公开渠道的检查、下载和重启必须在发版后另验一次。
- 发布配图可用 GPT Image 生成，沿用 Peek 标志和现有配色，用图表现本版主题；不拿生成图替代实机截图。README 继续展示浅色任务栏小组件，不放设置页或桌面浮窗。

## 安装与原生菜单

- 对最终 Inno EXE 记录 SHA-256，用临时标准账户检查默认位置、自选目录和安装后启动/卸载。看实际选择目录及完成页截图，检查安装器标志在当前显示缩放下清晰，不把设置页的应用图标或其他版本的安装截图当证据。
- 托盘、任务栏、桌面组件使用 Win32 `#32768` 菜单。检查显示、Esc、点外关闭、重新打开和至少一个命令；保留隐藏在设置之前，不创建 `WebViewPopups`。测试桥触发各套菜单项和真实系统点击的覆盖分别记录。用 `tests/PeekExplorerContextProbe.cs` 在有空余区域的 Explorer 桌面重复验证组件菜单点外关闭，并在系统任务栏菜单打开期间连续检查组件句柄、可见性及几何不变；不动现用实例。

颜色格式：浅色与深色均展开 HEX／RGB 检查主题、圆角和垂直中线；触发器与色值输入同高、同圆角、同字号；鼠标和键盘能切换，Esc 优先收起下拉，不应关闭整个颜色面板。实际取色单独验证回填与取消。

取色：使用真实鼠标从 Peek 窗口外取样，核对已知颜色的 HEX 和 RGB 回填；Esc 取消不得覆盖旧值，确定后重开验证保存。前台遮挡导致点击没到 Peek 不算通过。

## 内存回归

- 用 `tests/peek-memory-lifecycle.mjs` 在隔离配置采集宿主和 WebView2 进程树：静默启动不应创建 WebView2，打开后应有渲染进程，点关闭后短时间重开应保留快速首帧，闲置后浏览器子进程应退出。分别记录冷启动、短间隔重开、最小化、关闭后的专用工作集及首帧耗时。
- 安装测试结束确认测试配置和启动的进程都没有留在后台。不要把临时测试账户下的 Peek 算进正式实例。

## GitHub 发布流程

1. **对源提交**：以 GitHub 默认分支为基线，只纳入本次源码、版本变更、测试、文档及需要的资源。检查差异，不提交缓存、账号配置、临时负载、QA 目录或打包二进制。核对候选产物对应本次提交，再推送源码；不强推。
2. **草稿与资产**：新 `vX.Y.Z` 标签指向已推送并验收通过的准确提交。创建该版本的 GitHub Release 草稿，填写简短实际改动，上传 `Peek-Setup-vX.Y.Z.exe`、`Peek.exe` 和 `SHA256SUMS.txt`。核对标签、资产名称、版本、大小、SHA-256，以及更新器可识别安装包；不覆盖既有标签或资产。
3. **正式发布并验真**：草稿核对完再发布为正式版。匿名重新打开 Release tag、确认 `latest` 指向本版，下载两个 EXE 并比对 SHA-256。隔离启动上一正式版，核对检查到本版后能从公开渠道安装并重启，版本已更新、设置未丢。线上任一步失败都记录为发布回归失败，不声称发版验收完成；有修复时发递增的新版本。
4. **交付**：给出源码提交、标签、Release、直接可用的安装与便携 EXE 链接，并说明验证范围及未覆盖项。不要把 ZIP 或 MSI 当作用户的交付物。仅本地例外则给候选 EXE 路径、哈希和测试结果，不把它称作已发布版。
